# V2.0.5 Persistent UI Stability Candidate
Based on V2.0.4 faa3c9d; separate branch nat-ui-stability.
The observed 600 ม. route summary was not accepted by the prior distance regex; the old toolbar also depended on a uniquely recognized route summary. Now the map shortcut guard is separate from route-summary verification. A 164x78dp current and 198x94dp arrival view are independently placed on Activity content FrameLayout. Large arrival displays matching final forecast or the uniquely verified native summary (labelled Maps arrival, not necessarily final if charging stops exist); unverified values display a dash. Native summary stays visible intentionally; do not hide unknown native SOC/icons. Native touch targets retain priority, so if no safe slot exists a card can still be absent. The 1s existing scan recreates detached views, not a guaranteed persistent native lifecycle hook. Five controls are attempted whenever map controls are recognized; a single launcher provides all five actions if they cannot fit. Hold Clean to collapse; launcher Expand restores preference. Native EV action stays strictly guarded. Diagnostics captures last UI status when opened, including no-slot/no-data reasons. No extra API or location requests. Existing safe mode/focus checks remain. Real vehicle tests still needed for layout, touch, night theme and 30-min navigation. V3.0 and map-original unchanged.
