# NAT V3.0 Smart Split Screen — experimental candidate
Branch nat-split-screen, based on faa3c9d (V2.0.4). Default split preference true, opt out from Full Map or BYD Battery Settings. Changes only existing native child's FrameLayout.LayoutParams (no reparenting) when content is a landscape FrameLayout with one native MATCH_PARENT child, recognized map controls, zero margins and enough space (minimum 540dp map, 200dp panel). The right panel occupies floor(width/4). After two seconds checks child width, panel width, and visible SurfaceView/TextureView/map-button geometry; restores original params if the applied layout no longer fits. This is a structural guard, NOT proof of renderer/touch compatibility. Existing native arrival card retained; panel only reports arrival forecast when matching the native route heuristic. V2.0.4 overlay toolbar restored in Full Map. Panel buttons reuse native EV/clean actions, existing Energy/Plan snapshot dialogs, diagnostics and timeline; manual energy tariff remains in original full-map controls/settings. No extra paid API. Motion uses existing BYD speed samples (10s nominal, 15s freshness) and GPS bearing differences (500ms requested, actual cadence device-dependent, 3s freshness, speed >=5 km/h, accuracy checks). Turn graphic is illustrative heading trend, not steering angle, actual lanes, turn signal or ADAS. Canvas redraw max about 10fps when moving; stops when unavailable or focus lost. Cropped low-resolution car photo from user's uploaded image embedded; original photo/background not published. No location coordinates retained by this module. Existing opt-in trip recorder unchanged. Compile and parked vehicle tests required; no guarantee of true native split rendering or touch.
