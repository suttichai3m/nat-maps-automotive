# NAT V2.0.4 — Direct System Diagnostics shortcut
Adds an accessible 48dp circled-i button (System Diagnostics — CPU / RAM / GPS) after Clean Mode. On a verified route or owned search, the toolbar tries five buttons, then falls back to all four original actions if no safe five-button slot exists. Vertical/right is preferred, with left/horizontal alternatives. Without a verified route, a single diagnostics button can appear when native map controls are recognized, safe mode permits BYD features, NAT controls are enabled, the Maps window has focus, and a safe slot exists. If no safe slot exists, use BYD Battery Settings. No GPS fix or fresh forecast is required to open diagnostics from the idle map. No new location permissions or paid APIs. The button opens the existing read-only diagnostics dialog (Maps process); it closes any NAT panel, does not close native EV results or invoke Back/route cancellation. The dialog temporarily takes focus so overlays can be hidden and reconstructed after closing; it does not intentionally change navigation. Diagnostics retains pause/close lifecycle and adds duplicate-dialog protection. The export schema is backward-compatible (nat-diagnostics-2.0.3) with app_version 2.0.4. Use while parked.
Run existing nat-build.yml on map-original. No changes to battery calculation, native EV actions, energy/trip algorithms, theme or cloud builder. Regression tests exercise pure layout and fallback geometry; Android compile and real vehicle button/overlay lifecycle are separate validations.
