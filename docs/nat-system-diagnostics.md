# NAT V2.0.3 System Diagnostics
Open Maps > BYD Battery Settings > NAT System Diagnostics — CPU / RAM / GPS while parked. The existing separate Report process is not used for process CPU/PSS; it would measure the wrong process. CPU normalized across available logical cores using Process.getElapsedCpuTime and elapsedRealtime; PSS from Debug.getMemoryInfo (MiB), sampled at most every 10 s; system memory from ActivityManager.MemoryInfo; storage from StatFs. CPU/history every 2 s, 30 samples / 60 s maximum. GNSS callback and GPS-only location updates while monitoring, no coordinates stored, no new permissions, no paid APIs, no network upload. GPS permission/disabled/request unavailable/stale/fix and satellite data age are distinct. A fix is not claimed as 3D; used-in-fix comes from GNSS and doesn't itself prove a fresh position. Sky coordinates and signal strength are actual GNSS observations. BYD status is cached in Maps process, not new SDK calls. Export TXT and JSON to app-specific files, or copy JSON; no automatic sending. Pause/close/background stops monitoring, resume starts a new session. Other process CPU, system-wide CPU, chip temperature, and actual Maps frame timing not measured. History is session-only. Vehicle runtime must be validated. Build source and existing V2.0.2 logic unchanged except new read-only accessor and Settings button. No claim of zero overhead.
